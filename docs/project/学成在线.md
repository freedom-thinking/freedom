# 学成在线

这篇跟前几篇不太一样。前面那些是我自己动手做的，这篇是**跟着黑马程序员的教程做的**——学成在线，一个在线教育平台。

跟做它的目的很明确。我做过的项目不算少，但一直都是"一个人，从建库到写页面全包"。做多了会有一种感觉：代码我会写，但**一个真正企业级的项目到底是怎么从 0 走到 1 的**，我心里其实没数。团队怎么协作、代码怎么组织、为什么会有注册中心、网关、消息队列这些我没听过的东西——这些光靠自己闷头做小项目，是摸不到的。

所以跟着这套教程，从头到尾完整走了一遍。这篇不是"我做了个平台"，而是**一个学生第一次看清企业级开发长什么样的记录**。

## 学成在线是什么

它是一个在线教育平台：机构在上面发布课程，学员在上面选课、学习、看视频。

功能上大致几块：内容管理（课程信息、分类、审核）、媒资管理（视频和文件的上传处理）、课程搜索、课程发布、用户认证授权、选课学习。

听上去跟我之前做的项目也没差多少——不就增删改查加点业务逻辑吗？但真正跟下来才发现，**差别不在"做什么"，在"怎么做"**。

## 企业项目和自己写的项目，差在哪

我自己做项目，流程基本是：想清楚要做什么 → 建数据库 → 写接口 → 写页面 → 能跑就行。

这套教程里的流程，要"重"得多。

先是**需求分析和产品设计**——不是上来就写代码，而是先把"谁用、用来干嘛、有哪些角色、每个角色能做什么"理清楚。然后是**数据库设计**，表跟表的关系、字段、索引，先设计好再动手。接着是**接口设计**：前后端先把接口文档定下来（请求参数、返回结构都写清楚），**然后前端和后端各写各的，靠这份约定并行推进**。

这一点给我的冲击最大。我以前写代码是"边写边想"，写到哪算哪。企业里是**先想清楚、定下来，再动手**——因为在团队里，你一个人拍脑袋把接口改了，对接的人就得跟着返工。那份接口文档，就是前后端之间的"合同"。

再往后是联调、测试、部署。每一步都有它非做不可的理由。

## 为什么企业项目要用微服务

这是我这次最想搞明白的一块。

以前我做的项目都是"单体"——所有代码在一个工程里，打包成一个包部署。学成在线不一样，它是**微服务**：按业务拆成了好几个独立的小服务。

一开始我不理解：好好的一个项目，拆成这么多份，不是更麻烦吗？

跟下来才明白，拆是有代价，但**收益更大**。

单体应用的毛病在于：所有模块挤在一起，改一个地方就得把整个应用重新打包部署；想给访问量大的模块单独多加几台机器，做不到，因为它是一整坨；模块之间代码相互调用，边界越来越模糊，最后谁都不敢动。

拆成微服务之后，每个服务能独立开发、独立部署、独立扩容。内容管理改内容管理，媒资改媒资，互不影响；团队也能并行，一个组管一两个服务。

但拆完，冒出来一堆新问题——而正是这些新问题，构成了我觉得"企业级"最核心的部分：

**服务怎么找到彼此？** 拆散以后，服务 A 要调服务 B，可 B 的地址是会变的（重启、扩容都会变）。于是有了**注册中心**：每个服务启动时先去注册中心"报到"，要调谁就去注册中心查地址。

**外部请求怎么进来？** 用户不可能记住每个服务的地址。于是有了**网关**：所有外部请求先打到网关，网关再转发给对应的服务，顺带在这一层做统一的鉴权、限流。

**配置怎么统一管？** 十几个服务，每个都有自己的配置文件，改一个参数要挨个改一遍？于是有了**配置中心**，配置集中管理，改完各服务自动生效。

**某些活儿为什么不等它做完？** 比如课程发布后要同时更新搜索索引、发通知，这些要是卡着用户等，体验很差。于是有了**消息队列**，把耗时的活儿丢进去异步处理。

跟到这儿我才真正理解：**微服务不是为了显得高级，它拆出来的每一个组件，都是为了解决"拆分"带来的某个具体问题**。注册中心、网关、配置中心、消息队列，它们不是一串孤立的技术名词，而是这套架构里各管一摊事的零件，缺了谁都不行。

## 几个印象深的点

**认证授权**。用户登录后拿到一个 token，之后每次请求都带着它。可请求是经网关转发到后面的服务的，那后面的服务怎么知道"现在这个用户是谁"？这套流程走下来，我才算弄明白 JWT 到底是什么、网关统一鉴权是怎么回事、用户身份信息怎么在服务之间传下去。

**分布式文件存储**。视频这种大文件，不可能存在某台服务器的本地磁盘上——服务一重启、一扩容就出乱子。所以要有独立的文件存储服务，视频、图片、文档统一往里放。这也是我第一次接触到"文件不存本地"这种在企业里很常规的做法。

**接口先行**。前面提过一次，但值得再说一遍。前后端先把接口文档定死，再各写各的。这是团队协作里最重要的一个习惯，也是我自己单干时最缺的一环。

## 跟完之后

说实话，跟做不等于掌握。这十几个服务的代码，我不敢说每行都吃透了，很多地方是"跟着敲通了"，真让我从零独立设计一套，还早。

但这次跟做，补上了我认知里最大的一块空白：**我终于知道一个企业级项目长什么样了。**

以前我对"企业开发"的想象是模糊的——不就是代码写得规范点、用点高级框架吗？跟完才明白，它其实是一整套**流程 + 架构 + 协作规范**。代码只是其中一环，而且很可能不是最难的那一环。

对我来说，这套教程最大的价值，不是让我多会了几个框架，而是让我以后再看到一个企业项目时**不再一头雾水**——我能看懂它的分层、它的架构、它为什么这么组织代码。

这大概就是从"会写代码"往"懂做项目"迈的那一步。
