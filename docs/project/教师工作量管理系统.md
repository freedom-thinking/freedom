# 教师工作量管理系统

这个系统说白了就是帮学校统计教师的工作量。一个老师一学期下来，要记的东西其实挺杂的——上了多少课、带了几个班、发了什么论文、有没有指导学生、当没当班主任。以前这些全靠手工填表、拿 Excel 汇总，一到学期末统计就乱成一团。

我在里面负责前端，技术栈是 Vue3 + Element Plus，后端 SpringBoot，我主要做页面、对接接口。

选 Vue3 倒没什么惊天动地的理由，就是新项目不想再写 Vue2 那套 options API 了。组合式 API 写起来逻辑能聚到一块，不用像以前那样 data、methods、computed 到处翻，写多了确实舒服。Element Plus 就是 ElementUI 的 Vue3 版，后台那套组件——表格、表单、弹窗、下拉框、日期选择——基本都给你备好了，省得自己手搓样式。

真做起来才发现，后台系统最耗时间的不是"功能"，是**表单**。申报工作量的那个页面，字段一大堆：类型、数量、学期、备注……每个字段的校验规则都得一个个配。类型必须选、数量必须是数字还得大于零。Element Plus 的 el-form 自带 rules，但字段一多，prop 和 rules 对不上、校验不触发这种破事就冒出来了，得一个个排查。

```vue
<el-form :model="form" :rules="rules" ref="formRef">
  <el-form-item label="工作量类型" prop="type">
    <el-select v-model="form.type">
      <el-option label="教学" value="teaching" />
      <el-option label="科研" value="research" />
      <el-option label="其他" value="other" />
    </el-select>
  </el-form-item>
  <el-form-item label="数量" prop="amount">
    <el-input v-model.number="form.amount" />
  </el-form-item>
</el-form>
```

列表页反而是最省心的，el-table 配个分页、加几个筛选条件就完事，组件都是现成的，没怎么费劲。

坑的话，我印象深的大概这几个。

**ref 和 reactive**，一开始是真没分清。ref 包了对象忘了写 `.value`，改半天数据页面纹丝不动；reactive 的对象一解构，响应式直接丢了。后来硬记成一句话：基本类型用 ref，对象用 reactive，别混着来。

**跨域**。前端跑 5173、后端跑 8080，第一次联调浏览器就报 CORS，控制台红一片。开发环境配个 proxy 代理转发一下就好了，但第一次碰见是真懵，还以为接口写错了。

**token 过期**。登录拿到的 token 是有有效期的，过期了接口返回 401，要是不在响应拦截器里统一处理，用户正操作着突然就"未登录"了。后来补了个拦截，401 就清掉本地 token、跳回登录页。

```js
service.interceptors.response.use(
  res => res,
  err => {
    if (err.response?.status === 401) {
      localStorage.removeItem('token')
      router.push('/login')
    }
    return Promise.reject(err)
  }
)
```

做完回头看，后台系统门槛确实不高，套组件就能出活，但响应式、组件通信、拦截器这些东西，不自己踩一遍坑是吃不透的。前端这活，看着是画页面，功夫全在看不见的地方。
