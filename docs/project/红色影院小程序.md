# 红色影院小程序

这是课程设计做的东西。名字听着挺正式，实际就是把红色电影和党建活动这两件事塞进一个微信小程序里，让人不用跑线下，在手机上就能看排片、约场次、报名活动，顺带翻点党史内容。

做它没多想，课程设计要交，就挑了个自己够得着、又能把微信小程序那些知识点都串一遍的题材。红色主题的好处很实在，内容现成、方向明确，不至于做着做着跑偏，也不用为了编素材发愁。

## 技术栈没纠结，坑在别处

用微信原生小程序加云开发。前后端都是我自己啃，没有别人。

选原生是因为课程教的就是这个，小程序官方那套 WXML + WXSS + JS，再加个组件化的 WXS，跟学过的前端大同小异，上手不快不慢。云开发算是它顺带送的福利，云数据库、云函数、云存储三件套都有，不用自己搭服务器，不用管域名备案。对一个人做课程设计来说这是最省事的路，真要自己搞个后端，光部署和备案就能把时间吃光。

一开始我还担心过，云开发是不是不够正经，会不会显得像在偷懒。后来发现担心错了地方，真做起来的时候，坑全在别的角落。

## 选座那部分，我最想讲

页面不少，但真正花心思的就那么几块。

电影列表最简单，云数据库一张表，拉下来渲染，配个搜索和分类筛选，一个下午的事。

放映排期要想一下，电影不是想约就约的，得有场次，得存哪部片、哪天、哪个时间段、还剩多少座，排期表跟电影表关联起来。做完这一步我才意识到，排期只是个入口，真正的麻烦在座位。

在线选座是我觉得最像真东西的部分。一个场次几十个座位，怎么把「这个位置已经被占了」及时反映出来，是核心问题。

最笨的办法是用户点选座的时候，直接把选中的座位写进数据库然后刷新页面。这办法能跑，但一上线就出事——两个人同时选三排五座怎么办？A 先选了还没提交，B 也点了三排五座，结果两个人都显示「预约成功」，后写的把先写的盖掉，到了现场只有一个人有座。

```js
// 预约时用云数据库的原子操作，抢占座位
db.collection('seats').where({
  sessionId,
  seatNo: selectedSeat,
  status: 'free'        // 只有空闲状态才更新
}).update({
  data: { status: 'booked', userId: openid }
}).then(res => {
  if (res.stats.updated === 0) {
    // updated 是 0，说明这个座位刚刚被人抢走了
    wx.showToast({ title: '手慢了，座位已被约', icon: 'none' })
  }
})
```

思路就是在 where 里带上 `status: 'free'`，然后看 update 返回的 `stats.updated`。只有真把状态从空闲改成已约的那一次，updated 才是 1，其余全是 0。谁抢到就是谁，抢不到就提示重选，简单粗暴但管用。

这个机制想通之后，我才明白为什么大家老把「数据库的原子操作」挂在嘴边。以前我以为这是个很高深的东西，其实就是专门用来治这种「同时点」的毛病。抢座位、抢单、抢优惠券，本质是一回事。

选座页里中间那条弧线是银幕，座位分三种状态，可选是白的，自己选的是红的，已经被占的是灰的。

党建活动报名跟电影预约是两套逻辑。活动不选座，但要存谁报了、报了多少人、有没有上限。名额判断踩的是同一个坑，如果先查人数再判断再插入，中间隔的那一下就可能超员，所以还是条件更新那套，人数没满才允许插入。活动页每场显示时间地点和报名进度，名额满了按钮就置灰。

党史内容那块是纯内容页，图文列表加详情，没什么技术含量，纯粹是为了把红色题材的内容感撑起来，不然一个党建主题的小程序点进去全是功能，有点空。个人中心能看到自己的电影预约、活动报名和学习时长，页面朴素，但该有的都有。

## 权限和环境 ID，最冤的两个

云数据库的默认权限是「仅创建者可读写」，这个坑我踩得最冤。在开发者工具里测得好好的，一到真机就什么都读不出来，我还以为是数据没同步，折腾半天才发现是权限没放开。后来改成所有用户可读、仅创建者可写，电影列表这类公开数据才正常。

环境 ID 我也配错过。那串字符长得都差不多，一开始手滑写错一位，云函数全部调用失败，报错信息还看不出跟环境有关，最后是拿文档一行行对出来的。

还有一个现在已经成常识了：开发者工具和真机是两回事。云函数在工具里跑通了，真机上超时，查下来是本地调试和云端部署的环境变量没对上。这种「工具里好使、真机里不行」的差异在小程序里特别多，我后来养成了每个功能都拿真机预览过一遍的习惯，虽然很烦。
