# 简历编写

写简历这件事，很多人的做法是：打开 Word，对着空白页发呆，然后开始堆内容。结果是堆出一份谁看了都记不住的简历。

其实写简历是有章法的。它不是"写作文"，更像**做一道设计题**：给定一个目标（岗位），用有限的材料（你的经历），搭出一个能让 HR 快速看懂的结构。

我把整个流程拆成四步。注意，前三步都是准备，最后一步才真正动笔。

## 第一步：别急着写，先做功课

动手之前，先搞清楚两件事：**你要投什么岗位**，以及**这个岗位要什么**。

找 3~5 个目标岗位的 JD，摆在一起看。你会发现关键词是重复的——比如投后端，反复出现的就是 Java、SpringBoot、MySQL、Redis、微服务。

把这些重复出现的关键词列成一张单子。这张单子，就是你简历的"考点"。

## 第二步：盘点你的家底

拿着这张单子，回头翻自己：我有哪些经历能对上？

拿张纸（或者开个文档），把项目、实习、竞赛、课程设计全都列出来——先别管好坏，全都列。然后对着"考点单"筛：

- 能直接对上的 → 重点写
- 能勉强挂上钩的 → 想个角度往上靠
- 完全无关的 → 砍掉

这一步最反直觉的地方是：**你要允许自己扔掉很多东西**。你做过的事，远比你该写上去的多。简历不是日记，不用什么都记。

## 第三步：搭骨架

应届生简历的骨架基本是固定的几块：

1. **个人信息**：姓名、电话、邮箱（别放身份证号、家庭住址）
2. **教育背景**：学校、专业、时间、相关课程 / GPA
3. **技能清单**：按岗位要的分类列，别堆砌
4. **项目经历**：**重头戏**，通常放 2~3 个
5. **实习 / 校园经历**：有就写，没有不强求
6. **荣誉 / 证书**：挑跟岗位相关的

顺序上，**应届生的原则是"最有分量的放前面"**——科班 + 项目强，教育背景和项目就往前放；实习厉害，实习往前放。

## 第四步：填内容（这一步才叫"写"）

每一块怎么写都有讲究，但核心就一句：**用事实，别用形容词。**

拿项目经历举例。

差的写法：

> 参与开发了一个管理系统，负责前端开发，有一定的团队协作能力。

好的写法：

> 独立负责系统前端的全部页面搭建，基于 Vue3 + Element Plus 实现 12 个功能页面；对接后端 30+ 接口，用 Axios 拦截器统一处理 token 过期与错误提示。

差别在哪？后者全是**具体的名词和数字**——什么技术、多少个页面、多少个接口、具体做了什么。HR 看完，能想象出你干活的样子。

## 一份通用检查清单

写完之后，拿这几条过一遍：

- [ ] 一页以内（应届生）
- [ ] 每一行都在回答"我为什么适合这个岗位"
- [ ] 项目经历有具体技术、具体动作、具体结果
- [ ] 没有"认真负责""团队合作"这类空话
- [ ] 排版干净（字体不超过 2 种、没有花哨模板）
- [ ] 没有错别字（这条比你以为的重要）

## 最后

简历的本质，是**用有限的篇幅，证明"我跟这个岗位匹配"**。

它不需要你把自己写成完人，只需要让 HR 在十几秒里看到"这个人，对了"。

写简历的功夫，一半在写，一半在想——**想清楚对方要什么，比写得多漂亮更重要**。
